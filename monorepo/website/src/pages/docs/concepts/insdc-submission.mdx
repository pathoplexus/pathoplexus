This page describes how we currently submit data to INSDC. It is current practice and may change over time; the underlying commitments are set out in [Data Submission and Access](/about/governance/data-submission#2-data-submission-and-access) in our governance documents. The same process applies equally to consensus sequences, associated metadata, and any raw reads submitted alongside them.

[Open](/about/terms-of-use/data-use-terms#41-open-data) data (consensus sequences, metadata, and any raw reads submitted with them) will be made publicly available through the [INSDC databases (ENA, DDBJ, NCBI)](https://www.insdc.org/). To accomplish this, we will upload data on your behalf to [ENA](https://www.ebi.ac.uk/ena/browser/about). After successful submission to ENA (this typically takes up to 48 hours, sometimes longer) we will return the accessions of your sequences (and, if applicable, your raw reads) in ENA.

When submitting to ENA we use the `institution` on your group page as your `center name`, [center name](https://ena-docs.readthedocs.io/en/latest/submit/general-guide/programmatic.html#identifying-submitters) is used by ENA as an identifier to facilitate the recognition and attribution of your sequences within the INSDC.

We urge users to not upload their sequences independently to INSDC to prevent data duplication. However, if at any point in time Pathoplexus no longer exists and you need to modify your data you can use the `center name` to identify your group and request sequence revision.

## ENA Submission

In order to submit your sequences to ENA we need to create a Project, Sample and Assembly on your behalf, plus an Experiment and Run for any raw reads you submitted, see [ENA's metadata model](https://ena-docs.readthedocs.io/en/latest/submit/general-guide/metadata.html) for more information.

In ENA, Projects contain general information on your group and the organism being sequenced. We create one Project per each group and organism. In ENA Samples contain metadata information and Assemblies contain the actual sequences. We create one Sample and one Assembly object per consensus sequence, and additionally one Experiment and one Run object if you also submitted raw reads.

## Raw Reads

If you submit raw reads alongside a consensus sequence, they are submitted to ENA on the same terms as the consensus sequence and its metadata: once the data is Open (whether open from submission, or after a Restricted-Use period ends), the raw reads are uploaded to ENA together with the rest of the submission.

Raw reads are linked to the same ENA Sample as their consensus sequence, and are submitted as an Experiment and a Run object. Consensus sequences are linked to their associated raw reads via the Run accession.

If you have already submitted the raw reads for a sequence to the INSDC you can supply the appropriate accessions and we will ensure to link to the existing Run, BioSample, and BioProject when we submit consensus sequences on your behalf to the INSDC (see [Uploading raw reads](/docs/how-to/upload-raw-reads) for how to supply these accessions).

## Citing your Sequences

If you would like to cite your sequences in a publication you can use your Bioproject accession (this will start with `PRJ`), Biosample accession (this will start with `SAM`), INSDC accession(s) (varying prefix) and, for raw reads, the Run accession (starting with `ERR`). For segmented viruses, the assembly accession (starts with `GCA`) is ideal as it refers to all segments, however NCBI does not currently index GCA accessions, only ENA does.

## Mapping of Pathoplexus Metadata Fields to ENA Metadata Fields

To facilitate data standardization we map our metadata to ENA's [ENA virus pathogen reporting standard checklist](https://www.ebi.ac.uk/ena/browser/view/ERC000033), using PHA4GE's official mapping.
